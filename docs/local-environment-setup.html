01 · Orientation

What You Are Setting Up

A monorepo with three apps and a geospatial database. After this guide you will have every service running on your machine.

Backend API

Django 5.2 + DRF, JWT auth, Celery workers.

Python 3.12+:8000

Database

PostgreSQL 17/18 + PostGIS 3.6 (spatial data).

PostGIS:5432

Web Dashboard

Next.js 16 + Tailwind 4 + MapLibre maps.

Next 16:3000

Mobile App

Expo SDK 57 / React Native 0.86 in Expo Go.

Expo 57:8081

Cache & Queue

Redis 7 for cache + Celery broker.

Redis 7:6379

Repo Layout

apps/api · apps/web · apps/mobile · docs/

monorepo
Three rules that prevent 90% of setup issues
  • PostgreSQL must be 17 or 18 with the PostGIS extension (the shipped DB dump requires it).
  • Always run the API as runserver 0.0.0.0:8000 — plain runserver binds only localhost and Expo Go on a phone cannot connect.
  • The phone must use your PC's LAN IP (e.g. 192.168.1.4), never localhost.

03 · The Build

Setup Steps

Follow in order. Total time ≈ 30–45 minutes on a clean machine.

1

Get the code 2 min

Copy or clone the project, skipping generated folders.

powershell
git clone <repo-url>.git oneoceanonelife
cd oneoceanonelife

# or copy an existing working folder (exclude junk)
robocopy <source>\oneoceanonelife C:\projects\oneoceanonelife `
        /XD node_modules .next venv __pycache__ .ruff_cache /MIR

Note: XAMPP is not used — the web server is Django/Nginx and the database is PostgreSQL, not MySQL.

2

PostgreSQL + PostGIS database 10 min

Install PostgreSQL 17/18 (with PostGIS via Stack Builder or apt), then create the role, database and extensions.

sql — psql -U postgres
CREATE ROLE o3l_user WITH LOGIN PASSWORD 'o3l_password' SUPERUSER CREATEDB;
CREATE DATABASE o3l_dev OWNER o3l_user;
\c o3l_dev
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS postgis_topology;
CREATE EXTENSION IF NOT EXISTS fuzzystrmatch;
\dx   -- must list postgis, postgis_topology, fuzzystrmatch
3

GDAL / GEOS libraries Windows only

GeoDjango loads spatial DLLs from the PostgreSQL bin folder. Point apps/api/o3l/settings/development.py at yours.

python — apps/api/o3l/settings/development.py
GDAL_LIBRARY_PATH = os.environ.get('GDAL_LIBRARY_PATH', r'C:\PostgreSQL\18\bin\libgdal-35.dll')
GEOS_LIBRARY_PATH = os.environ.get('GEOS_LIBRARY_PATH', r'C:\PostgreSQL\18\bin\libgeos_c.dll')

Match the file names that actually exist in your bin folder — the version suffix changes per release. On macOS/Linux install gdal-bin libgdal-dev libgeos-dev instead.

4

Python environment + dependencies 8 min

powershell — apps/api
cd apps\api
python -m venv venv
.\venv\Scripts\Activate.ps1          # Git Bash: source venv/Scripts/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python manage.py check              # "System check identified no issues"

Shortcut: run bash setup.sh from the repo root (Git Bash) — it creates the venv and installs the packages for you. If activation is blocked: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.

5

Environment file 2 min

Create apps/api/.env with these development defaults:

env — apps/api/.env
DEBUG=True
SECRET_KEY=dev-secret-key-not-for-production-change-in-production
ALLOWED_HOSTS=localhost,127.0.0.1,192.168.*
DJANGO_SETTINGS_MODULE=o3l.settings.development

DB_NAME=o3l_dev
DB_USER=o3l_user
DB_PASSWORD=o3l_password
DB_HOST=localhost
DB_PORT=5432

REDIS_URL=redis://localhost:6379/0
JWT_ACCESS_TOKEN_LIFETIME=60
JWT_REFRESH_TOKEN_LIFETIME=7
CORS_ALLOWED_ORIGINS=http://localhost:3000,http://localhost:8081
6

Load the database fastest path

Restore the shipped dump (real data in seconds) or start empty and migrate + seed.

Option A — restore backup
from repo root
$env:PGPASSWORD='o3l_password'
psql -U o3l_user -d o3l_dev -w `
  -v ON_ERROR_STOP=1 -f docs\database-backup.sql
Option B — migrate + seed
apps/api
python manage.py migrate
python manage.py seed_zones
python manage.py seed_cms
python manage.py seed_data
python manage.py createsuperuser
7

Frontend dependencies 5 min

Web — apps/web
bash
cd apps/web
npm install
Mobile — apps/mobile
bash
cd apps/mobile
npm install
8

Start everything 3 min

Four terminals. Keep them open while you develop.

1 — API (bind ALL interfaces)
apps/api
.\venv\Scripts\Activate.ps1
python manage.py runserver 0.0.0.0:8000
# → localhost:8000 + LAN IP:8000 (for phones)
2 — Web
apps/web
npm run dev
# → http://localhost:3000
3 — Celery workers
apps/api
celery -A o3l worker -l info
# + celery -A o3l beat -l info
4 — Mobile (Expo Go)
apps/mobile
npx expo start -c
# scan QR with Expo Go
04 · Data

Database Backup

A verified plain-SQL dump ships with the project so you start with real content instead of an empty schema.

File

docs/database-backup.sql

Plain SQL

Contents

105 tables · 102 migrations · PostGIS extensions · seeded data

≈ 2.2 MB

Requires

PostgreSQL 17 or 18 (dump made with pg_dump 18.6)

pg_dump 18.6
Restore (Windows)
powershell — repo root
$env:PGPASSWORD='o3l_password'
psql -U o3l_user -d o3l_dev -w -v ON_ERROR_STOP=1 -f docs\database-backup.sql

# verify
psql -U o3l_user -d o3l_dev -w -c "SELECT count(*) FROM django_migrations;"   # 102
psql -U o3l_user -d o3l_dev -w -c "SELECT count(*) FROM users;"               # 319
Restore (macOS / Linux)
bash
PGPASSWORD='o3l_password' psql -U o3l_user -d o3l_dev -w -v ON_ERROR_STOP=1 \
  -f docs/database-backup.sql
Restore errors
  • unrecognized configuration parameter "transaction_timeout" → your server is PostgreSQL 16 or older; upgrade to 17/18.
  • permission denied to create extension "postgis" → restore as the postgres superuser.
  • Re-running the restore is safe — the dump uses --clean --if-exists.
05 · Acceptance

Run & Verify

Everything below should pass before you call the setup done.

Services
  • ✓API — http://localhost:8000/api/v1/ responds
  • ✓Admin — http://localhost:8000/admin/ sign-in works
  • ✓Web — http://localhost:3000 renders, no console errors
  • ✓Celery — worker logs “ready”
  • ✓Redis — redis-cli ping → PONG
Data & auth
  • ✓Migrations — SELECT count(*) FROM django_migrations; → 102
  • ✓PostGIS — SELECT postgis_version(); returns a value
  • ✓Tables — 105 public tables present
  • ✓Login — POST /api/v1/auth/login/ returns JWT tokens
  • ✓Admin user — your superuser can access /admin/
powershell — one-shot smoke test
foreach ($u in @('http://localhost:8000/api/v1/','http://localhost:3000')) {
  try { $r = Invoke-WebRequest $u -UseBasicParsing -TimeoutSec 8
        Write-Host "OK  $($r.StatusCode)  $u" -ForegroundColor Green }
  catch { Write-Host "FAIL       $u  — $($_.Exception.Message)" -ForegroundColor Red }
}

06 · Physical Device

Expo Go on a Real Phone

The most common first-day blocker. The phone is a different machine — it cannot see your PC's localhost.

Login Failed — “Cannot reach server — is the API running?” Almost always one of these three. Fix them in this order:
1

Bind the API to all interfaces

apps/api
python manage.py runserver 0.0.0.0:8000
# ✗ python manage.py runserver      → 127.0.0.1 only → phone refused
# ✓ 0.0.0.0:8000                    → reachable on your LAN IP
2

Point the app at your PC's LAN IP

Find the IP with ipconfig (Wi-Fi adapter → IPv4, e.g. 192.168.1.4).

env — apps/mobile/.env
EXPO_PUBLIC_API_URL=http://192.168.1.4:8000/api/v1

Restart Metro with a clean cache so the variable is inlined: npx expo start -c.

3

Open the firewall (elevated PowerShell)

run as Administrator
netsh advfirewall firewall add rule name="O3L API 8000" dir=in action=allow protocol=TCP localport=8000

Phone and PC must be on the same Wi-Fi. Disable hotspot/client isolation and any VPN on either side.

Quick reachability check (from the PC)
powershell
Invoke-WebRequest http://192.168.1.4:8000/api/v1/auth/login/ -Method POST `
  -ContentType 'application/json' -Body '{"username":"x@y.com","password":"nope"}'
# 401 Unauthorized = server reachable, credentials just wrong  ✓
# timeout / refused = bind address or firewall problem         ✗
USB alternative (Android)With the phone on USB debugging, run adb reverse tcp:8000 tcp:8000 and set EXPO_PUBLIC_API_URL=http://localhost:8000/api/v1 — the phone's localhost is then tunnelled to your PC.
07 · Support

Troubleshooting

The errors new developers hit most, and the fix that works.

+ “Cannot reach server” in Expo Go▾

See the Expo Go section above. Checklist: API on 0.0.0.0:8000, EXPO_PUBLIC_API_URL uses the PC's LAN IP, firewall allows TCP 8000, same Wi-Fi network. Restart Metro with npx expo start -c after changing .env.

+ GDAL / GEOS DLL load error on Windows▾

Update GDAL_LIBRARY_PATH / GEOS_LIBRARY_PATH in apps/api/o3l/settings/development.py to the actual DLL names inside your PostgreSQL bin folder (the suffix, e.g. libgdal-35.dll, changes per version). On macOS/Linux install gdal-bin libgdal-dev libgeos-dev.

+ type "geography" does not exist during migrate▾

PostGIS is not installed in the database. Run CREATE EXTENSION IF NOT EXISTS postgis; in o3l_dev, then re-run python manage.py migrate.

+ Port already in use (8000 / 3000 / 5432)▾
powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen |
  Select-Object OwningProcess, @{n='P';e={(Get-Process -Id $_.OwningProcess).Name}}
Stop-Process -Id <PID> -Force

# or use another port
python manage.py runserver 0.0.0.0:8001
+ Activate.ps1 blocked by execution policy▾

Run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, or use Git Bash with source venv/Scripts/activate.

+ Redis connection refused / Celery won't start▾

Start Redis: Windows → Memurai (winget install Memurai.MemuraiDeveloper) or Redis in WSL2; macOS → brew services start redis; Linux → sudo systemctl start redis-server. Verify with redis-cli ping → PONG.

+ CORS / 401 when the web app calls the API▾

Set CORS_ALLOWED_ORIGINS=http://localhost:3000,http://localhost:8081 in apps/api/.env, restart Django, and confirm the web app uses NEXT_PUBLIC_API_URL=http://localhost:8000/api/v1.

+ Next.js build fails or shows stale UI▾
bash — apps/web
rm -rf .next node_modules && npm ci && npm run dev
