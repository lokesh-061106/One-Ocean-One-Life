03 · Path 01

Local Machine Setup (Manual)

The exact sequence used to bring this project up on a fresh Windows workstation with native PostgreSQL — the same commands work on macOS and Linux with shell differences noted.

1

Copy the project onto the machine 5 min

Transfer the whole oneoceanonelife/ folder (zip, LAN share or Git). Exclude bulky generated folders if you want a lighter copy.

powershell — clone or copy
# Option A — from Git
git clone <your-repo-url>.git oneoceanonelife
cd oneoceanonelife

# Option B — copy an existing working folder (exclude junk)
robocopy I:\xampp8212\htdocs\oneoceanonelife C:\projects\oneoceanonelife `
        /XD node_modules .next venv __pycache__ .ruff_cache /MIR /NFL /NDL
XAMPP is not usedEven though the project lives under htdocs, O3L does not run on Apache/MySQL. The web server is Django's dev server (or Nginx) and the database is PostgreSQL + PostGIS. XAMPP can stay installed and untouched.
2

Install PostgreSQL + PostGIS & create the database 15 min

Install PostgreSQL 17/18 from the EDB installer, then add PostGIS 3.6 through Stack Builder (or apt install postgis on Linux).

sql — run as the postgres superuser
-- Connect: psql -U postgres
CREATE ROLE o3l_user WITH LOGIN PASSWORD 'o3l_password' SUPERUSER CREATEDB;
CREATE DATABASE o3l_dev OWNER o3l_user;

\c o3l_dev
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS postgis_topology;
CREATE EXTENSION IF NOT EXISTS fuzzystrmatch;
\dx          -- must list postgis, postgis_topology, fuzzystrmatch
Keep the credentials consistentDev defaults used everywhere in this project: database o3l_dev, user o3l_user, password o3l_password, host localhost:5432. If you choose different values, update apps/api/.env accordingly.
3

Configure GDAL / GEOS for GeoDjango Windows only

GeoDjango loads spatial libraries from DLLs at runtime. On Windows these live in the PostgreSQL bin folder (installed with PostGIS). Set the paths in apps/api/o3l/settings/development.py or via environment variables.

python — apps/api/o3l/settings/development.py
# Point these at YOUR PostgreSQL installation directory
GDAL_LIBRARY_PATH = os.environ.get('GDAL_LIBRARY_PATH', r'C:\PostgreSQL\18\bin\libgdal-35.dll')
GEOS_LIBRARY_PATH = os.environ.get('GEOS_LIBRARY_PATH', r'C:\PostgreSQL\18\bin\libgeos_c.dll')
powershell — alternative: set user environment variables
[Environment]::SetEnvironmentVariable('GDAL_LIBRARY_PATH', 'C:\PostgreSQL\18\bin\libgdal-35.dll', 'User')
[Environment]::SetEnvironmentVariable('GEOS_LIBRARY_PATH', 'C:\PostgreSQL\18\bin\libgeos_c.dll', 'User')
Wrong DLL path = startup crashIf you see OSError: ... or Could not find the GDAL library, the path/version suffix (libgdal-35.dll) does not match your install. Check what libgdal-*.dll and libgeos_c.dll actually exist in your PostgreSQL bin folder.
4

Restore the database backup recommended

Instead of seeding from zero, load the shipped dump so you start with real zones, CMS pages, guide species and demo users. Full details in the Database Backup section.

powershell — restore docs/database-backup.sql
cd oneoceanonelife
$env:PGPASSWORD='o3l_password'
psql -U o3l_user -d o3l_dev -w -v ON_ERROR_STOP=1 -f docs\database-backup.sql

# Quick sanity check
psql -U o3l_user -d o3l_dev -w -c "SELECT count(*) FROM django_migrations;"   # 102
psql -U o3l_user -d o3l_dev -w -c "SELECT count(*) FROM users;"               # 319

Testing on a real phone (Expo Go)? A phone cannot use localhost — that is the phone itself. Three things must line up:
  • Run the API as python manage.py runserver 0.0.0.0:8000 — plain runserver binds only 127.0.0.1 and the app fails with “Cannot reach server — is the API running?”
  • Point the app at your PC's LAN IP: EXPO_PUBLIC_API_URL=http://192.168.1.x:8000/api/v1 in apps/mobile/.env (find the IP with ipconfig)
  • Allow Python through the firewall (elevated shell): netsh advfirewall firewall add rule name="O3L API 8000" dir=in action=allow protocol=TCP localport=8000
Phone and PC must share the same Wi-Fi (disable hotspot/AP isolation). Quick check: open http://192.168.1.x:8000/api/v1/auth/login/ in the phone browser — you should get a JSON error, not a timeout.
9

Redis & Windows notes easy to miss

  • Redis is required for Celery and caching. On Windows install Memurai Developer (winget install Memurai.MemuraiDeveloper) or run Redis inside WSL2.
  • Execution policy blocks Activate.ps1 — fix with Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.
  • Port already in use — stop other dev servers, or run python manage.py runserver 8001 and update NEXT_PUBLIC_API_URL.
  • PostGIS must exist before migrations run, otherwise spatial fields fail with OperationalError: type "geography" does not exist.

    05 · Data

    Database Backup & Restore

    A verified, human-readable PostgreSQL plain-SQL dump ships with this guide so a new machine starts with real content instead of an empty schema.

    File

    docs/database-backup.sql

    Plain SQL

    Size

    ≈ 2.2 MB (uncompressed dump of a 37 MB database)

    10,899 lines

    Source

    o3l_dev on PostgreSQL 18.6 + PostGIS 3.6

    pg_dump 18.6

    Contents

    105 tables · 102 migrations · ~1,900 rows · extensions

    Schema + Data
    What Is Inside The Dump
    • Schema — all 105 tables, indexes, sequences, constraints, views and functions.
    • Data — seeded coastal zones, districts, villages, guide species, CMS pages, education content, demo users, events and marketplace records.
    • Extensions — postgis, postgis_topology, fuzzystrmatch, plpgsql.
    • Ownership stripped — dumped with --no-owner --no-privileges so it restores cleanly under any role.
    • Clean restore enabled — --clean --if-exists means you can re-run the restore safely.
    bash — how this backup was produced
    pg_dump -U o3l_user -d o3l_dev \
  --clean --if-exists \
  --no-owner --no-privileges \
  --encoding=UTF8 \
  -f docs/database-backup.sql
    Restore — Option A: Native PostgreSQL (local machine)
    1

    Create a superuser-owned empty database

    powershell / bash
    psql -U postgres -c "CREATE ROLE o3l_user WITH LOGIN PASSWORD 'o3l_password' SUPERUSER CREATEDB;"
psql -U postgres -c "CREATE DATABASE o3l_dev OWNER o3l_user;"

    The restore itself creates the extensions, so the role must be allowed to create them (superuser, or a trusted-extension capable role).

    2

    Load the dump

    powershell — Windows (run from repo root)
    $env:PGPASSWORD='o3l_password'
psql -U o3l_user -d o3l_dev -w -v ON_ERROR_STOP=1 -f docs\database-backup.sql
# exit code 0 = success
    bash — macOS / Linux
    PGPASSWORD='o3l_password' psql -U o3l_user -d o3l_dev -w -v ON_ERROR_STOP=1 \
  -f docs/database-backup.sql
    3

    Verify the restore

    sql — sanity queries
    SELECT count(*) FROM pg_tables WHERE schemaname='public';   -- 105
SELECT count(*) FROM django_migrations;                 -- 102
SELECT count(*) FROM users;                              -- 319
SELECT extname FROM pg_extension ORDER BY 1;             -- postgis ...
SELECT postgis_version();                                -- works = OK
    Restore — Option B: Inside Docker Compose
    powershell — stream the dump into the o3l_db container
    # stack must be running (docker-compose up -d) with db healthy
Get-Content docs\database-backup.sql -Raw | docker-compose exec -T db psql -U o3l_user -d o3l_dev -w

# alternative: copy the file in first, then restore
docker cp docs\database-backup.sql o3l_db:/tmp/backup.sql
docker exec -i o3l_db psql -U o3l_user -d o3l_dev -w -v ON_ERROR_STOP=1 -f /tmp/backup.sql
    Restore — Option C: Production VPS
    bash — Ubuntu server
    scp docs/database-backup.sql root@YOUR_VPS_IP:/tmp/
ssh root@YOUR_VPS_IP

# as the postgres superuser
sudo -u postgres psql -c "CREATE DATABASE o3l_prod OWNER o3l_user;"
sudo -u postgres psql o3l_prod < /tmp/database-backup.sql
    Taking A Fresh Backup Later
    bash — local / server
    pg_dump -U o3l_user -d o3l_dev --clean --if-exists \
  --no-owner --no-privileges --encoding=UTF8 \
  -f docs/database-backup-$(date +%Y%m%d).sql

# compressed variant (smaller, needs pg_restore)
pg_dump -U o3l_user -d o3l_dev -Fc -f o3l_dev.dump
    bash — production cron (already installed by deploy.sh)
    # daily at 02:00 → /var/backups/o3l/
o3l-backup

# manual restore
sudo -u postgres psql o3l_prod < /var/backups/o3l/db_20261014_020000.sql
    Restore troubleshooting
    • unrecognized configuration parameter "transaction_timeout" → server is PostgreSQL 16 or older; upgrade to 17/18.
    • permission denied to create extension "postgis" → restore as the postgres superuser, or grant the role superuser for the import.
    • database "o3l_dev" already exists messages → harmless: the dump uses --clean --if-exists and drops objects before recreating them.
    • invalid byte sequence → make sure you restore with UTF8 (the dump header sets it automatically) and do not re-save the file in another encoding.

    Live / Production Deployment

    Bare-metal Ubuntu VPS deployment with Gunicorn, systemd, PM2, Nginx, Let's Encrypt SSL and automated backups. Scripts live in deploy/hostinger/ and work on any Ubuntu 22.04/24.04 server.

    Server Sizing

    Hostinger VPS KVM 2 or higher: 4 GB RAM, 2 vCPU, 50 GB storage. Ubuntu 22.04/24.04 LTS with root SSH access.

    DNS

    Point the domain at the VPS: A  @ → VPS_IP and A  www → VPS_IP. DNS must resolve before SSL issuance.

    Access

    SSH key authentication, non-root o3l deploy user, UFW firewall (22/80/443) and Fail2Ban enabled by the setup script.

    09 · Support

    Troubleshooting

    The failures seen most often on a new machine, with the fix that actually works.

    + Django crashes with a GDAL / GEOS / DLL load error▾

    GeoDjango cannot find its native libraries. On Windows these come from the PostGIS install, not from pip.

    • Locate libgdal-*.dll and libgeos_c.dll inside your PostgreSQL bin directory (e.g. C:\PostgreSQL\18\bin).
    • Update GDAL_LIBRARY_PATH / GEOS_LIBRARY_PATH in apps/api/o3l/settings/development.py — note the version suffix in the DLL name changes per release.
    • On Linux/macOS install gdal-bin libgdal-dev libgeos-dev instead.
    + type "geography" does not exist during migrate▾

    The PostGIS extension is missing in the target database. Create it, then re-run migrations:

    sql
    \c o3l_dev
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS postgis_topology;
    + Expo Go login fails: “Cannot reach server — is the API running?”▾

    The phone reached the app (Metro on :8081) but cannot reach the Django API on :8000. In order of likelihood:

    • API bound to loopback — python manage.py runserver listens only on 127.0.0.1. Restart it as python manage.py runserver 0.0.0.0:8000.
    • Wrong URL in the app — the phone cannot use localhost. Set EXPO_PUBLIC_API_URL=http://<PC-LAN-IP>:8000/api/v1 in apps/mobile/.env (find the IP with ipconfig, e.g. 192.168.1.4) and restart Expo with npx expo start -c.
    • Windows Firewall — allow inbound TCP 8000 from an elevated shell:
      netsh advfirewall firewall add rule name="O3L API 8000" dir=in action=allow protocol=TCP localport=8000
    • Network mismatch — phone and PC must be on the same Wi-Fi; disable hotspot/client isolation and VPNs on either side.
    powershell — verify from the PC that the LAN path works
    Invoke-WebRequest http://192.168.1.4:8000/api/v1/auth/login/ -Method POST `
  -ContentType 'application/json' -Body '{"username":"x@y.com","password":"nope"}'
# 401 Unauthorized  = server reachable, credentials just wrong (good)
# timeout / refused = bind address or firewall problem
    + Port already in use (8000 / 3000 / 5432)▾
    powershell — find & free the port
    Get-NetTCPConnection -LocalPort 8000 -State Listen |
  Select-Object OwningProcess, @{n='Process';e={(Get-Process -Id $_.OwningProcess).Name}}
Stop-Process -Id <PID> -Force

# or just run on another port
python manage.py runserver 8001

    If you change the API port, update NEXT_PUBLIC_API_URL for the web app and CORS_ALLOWED_ORIGINS for the API.

    + CORS / 401 errors from the web app▾

    The browser origin is not allowed by the API. Ensure CORS_ALLOWED_ORIGINS in apps/api/.env contains http://localhost:3000 and http://localhost:8081 (Expo), restart Django, and confirm NEXT_PUBLIC_API_URL points at http://localhost:8000/api/v1.

    + Activate.ps1 blocked by execution policy▾
    powershell (admin)
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

    Or use Git Bash: source venv/Scripts/activate.

    + Redis connection refused (Celery won't start)▾

    Redis is not running. On Windows install Memurai (winget install Memurai.MemuraiDeveloper) or run Redis in WSL2; on Linux/macOS sudo systemctl start redis-server / brew services start redis. Verify with redis-cli ping.

    + Database restore fails on an older PostgreSQL▾

    Errors such as unrecognized configuration parameter "transaction_timeout" or invalid command \restrict mean the server/psql is older than 17. Upgrade PostgreSQL to 17 or 18 — the shipped dump was produced by pg_dump 18.6 and older servers cannot read it.

    + Next.js build fails or shows stale UI▾
    bash — clean rebuild
    cd apps/web
rm -rf .next node_modules
npm ci
npm run build   # or: npm run dev
    + Live site returns 502 Bad Gateway▾
    • Gunicorn socket down: sudo systemctl status o3l-api.socket and ls -la /run/gunicorn/o3l.sock
    • Nginx config broken: sudo nginx -t
    • Next.js not running: pm2 status → pm2 restart o3l-web
    • Inspect app errors: sudo tail -f /var/log/o3l/error.log
